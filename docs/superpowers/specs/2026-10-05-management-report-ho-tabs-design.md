# Management Report: 3 tabs, HO Report, two-sheet export - Design

Date: 2026-10-05
Status: Draft for user review
Builds on: the Management Report module (`app/modules/management_report/`), which already has Excel sync, snapshots, the Report view and per-CC export (single sheet).

## Goal
The master workbook `Management Report - MASTER.xlsb` produces two outputs per cost center: sheet `Report` (pivot `MR_1`) and sheet `BGT HO Report per CC` (the "HO Report"). Flow must show both and export both.

- Tab 1 **Data Sync**: sync from Excel and sync history (today's top card).
- Tab 2 **Report**: the existing Report view.
- Tab 3 **HO Report**: reproduction of sheet `BGT HO Report per CC`.
- "Export CC ini" and "Export semua CC (ZIP)" produce, per CC, ONE workbook with TWO sheets: `Report` and `HO Report`.

## How the Excel HO sheet works (verified on the master file)
- Every amount is `=XLOOKUP(<GL code>, Report!M:M, Report!N:N|O:O|P:P, 0) * 1000`, i.e. a lookup into the small pivot `MR_2` (COA x Sum of BGT/PTA/ACT) on sheet Report, in Rp 000. `MR_2` shares the slicers CC and MM with `MR_1`; it is not tied to the YY or COA page filters.
- Three stacked sections (rows in the Excel sheet): Capex per GL (1-44), Operating Expense per GL with group subtotals (47-263), Operating Expense Summary per group (267-298).
- 190 GL accounts, no duplicates. The template covers 64 of the 66 COAs in Append1; not covered today: `71000110` (ACT -97.5 in POCFAD) and `70004112` (ACT 0.1 in TFEDIR). Excel shows this in the control block H:K (`This Report` vs `PVT Table` -> FALSE).
- Four template rows carry the note "COA unit, tidak ada di HO" (column G): 70004113, 701193100, 701078002, 701078003.
- Subtotals are `SUM` of the group's accounts; Opex grand total = sum of group totals; summary rows are sums of explicit account lists (e.g. non-staff salary = rows 72-83 + 100-104).
- Headers: period label `s/d <Mon>` = `TEXT(Parameter!B2,"mmm")` (B2 = 31-Aug-26); `Division/Dept.` cell is wired to the YY filter by mistake and always shows "All"; the summary title hard-codes "Budget 2025".
- Report title: `"President Office & ETF – " & XLOOKUP(CC, Report!U10:U100, Report!V10:V100)` (short CC descriptions are a constant list in Report!U:V).

## Decisions (agreed with user)
- Three tabs as above; filters CC/YY/MM shared; the COA filter is shown on the Report tab only (HO is grouped by COA; matches `MR_2`).
- HO template = static file extracted once from the Excel sheet (see below); not read at every sync.
- COA not in the template: HO figures stay as the template defines them; the screen shows a warning and the export adds a footnote under Grand Total (e.g. "Tidak termasuk COA 71000110: ACT -97.500").
- Period label comes from `Parameter!B2` at sync time (not from the MM filter).
- Export always has both sheets, also for "All Cost Center".

## 1. HO template
File `app/modules/management_report/ho_template.json`, generated by `app/scripts/extract_ho_template.py` (uses Excel COM on a copy of the master file; re-run when the Excel template changes, e.g. a new GL account).

Content:
```
{ "org": "President Office & ETF", "location": "Head Office - Jakarta",
  "capex":  {"title": "Budget - Capital Expenditure (in Rp. 000)",
             "groups": [{"title": "NON FACTORY MACHINE", "total_label": "Total - Non Factory Machine",
                         "accounts": [{"code": "27001010", "name": "...", "note": null}, ...]}, ...],
             "grand_label": "Total Capex"},
  "opex":   {"title": "Budget - Operating Expense (in Rp. 000)", "groups": [...],
             "grand_label": "Grand Total included Depreciation"},
  "summary": {"title": "Operating Expense Summary (in Rp. 000)",
              "rows": [{"nomor": "701 - 01 - xxx", "label": "Repair And Maintenance Expense",
                        "codes": ["70101101", ...]}, ...], "total_label": "Total"} }
```
- Group order, account order, labels and notes are exactly as in the sheet (including the two groups both labelled "Total - 701-10-xxx", the blank-description row 169/235 is dropped as it has no GL code).
- Account lists per group and per summary row are derived from the Excel formula ranges (e.g. `SUM(D72:D83,D100:D104)`), not guessed.
- The summary section title is rendered as `Budget <year> - Operating Expense Summary (in Rp. 000)`; the year is the data year (`yy` filter or the latest year in the snapshot), never hard-coded.

## 2. Calculation (`ho_report.py`)
`build_ho_report(company_id, cc, yy=None, mm=None) -> dict` (cc `None` = all cost centers).
1. Aggregate the active snapshot by COA (SUM bgt, pta, act) with the same filters as Report (CC, YY, MM; no COA filter).
2. Amount per account = aggregate x 1000; accounts without data = 0.
3. Group total = sum of its accounts; section grand total = sum of group totals; summary row = sum of its `codes`; summary total = sum of rows.
4. `unmapped`: COAs present in the filtered data that are in no template account: `[{"coa", "bgt", "pta", "act"}]` x 1000.
Return shape:
```
{"title": ..., "period_label": "s/d Aug", "year": 2026,
 "capex": {"groups": [{"title", "rows": [{"code","name","note","bgt","pta","act"}], "total": {...}}], "grand": {...}},
 "opex":  {same}, "summary": {"rows": [{"nomor","label","bgt","pta","act"}], "total": {...}},
 "unmapped": [...], "has_data": bool}
```
Invariants (tested): opex grand == summary total; opex grand + capex grand + unmapped == Report grand x 1000 (per CC and for All).

## 3. Sync metadata
At sync, besides sheet Append1, read:
- Report!U10:V100 -> CC description map `{cc: description}` (blank rows skipped);
- Parameter!B2 -> report period (date, stored as ISO date; label `s/d <Mon>` derived);
- HO!A1 -> organisation name for titles.
Stored as JSON in new column `meta` of `mr_upload` (auto-migrated like `content_hash`). `meta` is part of the content hash, so a changed description or period counts as a change; the change summary notes "metadata berubah". A missing sheet/cell does not fail the sync: that field is left empty and titles fall back to the CC code.

## 4. UI
- Tabs "Data Sync | Report | HO Report" using the app's existing tab pattern; deep link `?tab=sync|report|ho`, default `report` (or `sync` when no data yet).
- Shared filter bar (CC incl. All Cost Center, YY, MM; COA on the Report tab only) with the existing live refresh; the HO tab fetches `/management-report/ho-table` (HTML fragment).
- HO tab shows the three sections as in Excel (all template rows, zeros as "-", Rp 000), the period label, and a warning box when `unmapped` is not empty ("COA di luar template HO tidak ikut dihitung: ...").
- Report title uses the CC description (`President Office & ETF – <description>`; "All" for All Cost Center).

## 5. Export
Workbook per CC, sheets in this order: `Report` (existing layout, title now with CC description), `HO Report`.
`HO Report` layout (values only, Arial 11): A1 organisation (16 bold, blue), A2 location, A4 `Division/Dept.: <CC description>`, then each section: section title, two-row header (`GL Account | Description | | Budget | PTA | Actual`, second row `s/d <Mon>`), group header rows, account rows (code shown `000-00-000`, name, amounts), group total rows, section grand total. Columns A 16.5, B 51, C 8.5, D 15, E 9, F 13.5, G 1 (notes in G overflow). Fills: header light yellow `FFFF99`, amount cells light cyan `CCFFFF`, totals bold blue `0000FF` with bottom border. Number format `#,##0;(#,##0);"-"`. Footnote under each Grand Total when `unmapped` is not empty. Freeze panes below the first header.
ZIP: one `<CC>.xlsx` per CC with data (empty CCs skipped), unchanged naming rules.
`build_cc_workbook(report, filters, ho_report)` gains the HO data; callers build both.

## Errors / edge cases
- No active snapshot or no data for the filter: HO tab shows the same empty state as Report; export returns 404 as today.
- Snapshot synced before this feature (no `meta`): titles fall back to the CC code and the period label is blank until the next sync; HO still works.
- Template and data disagree (unmapped COA): warning + footnote, never an error.

## Testing
- Unit: template shape (190 accounts, no duplicate codes, every summary code exists in the template), `build_ho_report` arithmetic and invariants, unmapped detection, metadata parse/hash.
- Cell-by-cell reconciliation of the HO figures for CC `TFKHAR` (all three sections) against the values read from sheet `BGT HO Report per CC` of the master file.
- Cross-check on 2-3 other CCs by driving the CC slicer in Excel on a copy of the master file and comparing its HO sheet with Flow (skipped when Excel is unavailable).
- Routes: tabs/deep links, `/ho-table` fragment with filters, export workbook has sheets `Report` and `HO Report`, ZIP entries contain both sheets.
- Browser check of the HO tab on a throwaway instance with the real master file.

## Out of scope
Reading the HO template from the workbook at every sync; hiding zero rows on screen; editing the template in the UI; the control block H:K (replaced by the unmapped warning); Supabase sync of the new data.
