Financehub (FLOW) - Financial Ledger & Operational Workspace

Sistem manajemen pengajuan pembayaran, realisasi anggaran, dan dashboard operasional tersentralisasi — dibangun di atas Python (Flask), SQLite, dan Vanilla HTML/JS.

BUSINESS LAYER — NON-TECHNICAL READERS

1 Executive Summary / Ringkasan Eksekutif

Financehub (FLOW) adalah sistem manajemen keuangan berbasis web yang dibangun untuk menggantikan proses manual (kertas/email/excel) di Sinar Mas Tjipta (SMT) dan Eka Tjipta Foundation (ETF). Sistem ini menghadirkan alur persetujuan digital (approval workflow) yang terstruktur, terekam, dan dapat diaudit secara real-time.

PLATFORM
Python Flask Web App
DATABASE
SQLite (finance_hub.db)
FRONTEND
HTML Service Templates (Vanilla)
USER ROLES
Requester, Verificator, Releaser, Admin

2 Problem Statement / Latar Belakang & Tujuan

2.1 Masalah Sebelumnya

  • Formulir dan pencatatan excel yang beredar antar departemen tanpa tracking status tersentralisasi.
  • Tidak ada visibilitas real-time sisa anggaran (budget) sebelum mengajukan Payment Memo.
  • Tidak ada audit trail yang dapat ditelusuri per dokumen.
  • Data tersebar — tidak ada satu sumber kebenaran (single source of truth) untuk SMT & ETF.

2.2 Solusi & Tujuan Sistem

  1. Portal Terpusat — Pengajuan (Memo, Beasiswa) terpusat, tersimpan di database lokal.
  2. Alur Persetujuan Bertingkat — Otomatisasi status dokumen (Draft → In_Review → Approved).
  3. Validasi Budget — Pengecekan otomatis batas budget vs realisasi.
  4. Dashboard Analitik (Premium UI) — Visualisasi Chart.js untuk tingkat eksekutif.
  5. Native Backup — Fitur admin untuk mencadangkan database secara langsung.

9.2 Session Object (JWT Payload) & Middleware

// Struktur Payload (Claims) JWT di Cookie "fh_access" (di-generate di auth/routes.py)
{
    "identity": "1",          // User ID Primer
    "username": "admin",      // Username operasional
    "role": "releaser",       // Tingkat Kasta Akses Kontrol
    "exp": 1735689600         // Expiration Date (Unix Timestamp)
}

Pengendalian akses diregistrasi di auth/middleware.py menggunakan dekorator kustom:

  • @jwt_html_required: Memverifikasi kehadiran cookie JWT. Jika absen/expired → Intercept & Redirect paksa ke /login.
  • @json_required: Digunakan untuk fungsi AJAX/Fetch. Jika akses ditolak, mencegah render HTML dengan membuang respon HTTP 401 JSON.
  • @html_admin_required: Menyekat rute hanya untuk is_admin() (mengevaluasi claims.role == "admin" atau username "admin").

10 Non-Functional Requirements / Batasan & Risiko

10.1 Platform Constraints (Waitress Server & SQLite)

ConstraintDetail Teknis
Database ConcurrencyKarena sistem basis data bertumpu pada arsitektur file-based SQLite, penguncian berkas (file locking) .db-journal bisa terjadi apabila terdapat penulisan data (Write Operations) yang sangat intens. Aplikasi ini aman untuk penggunaan paralel puluhan user SMT/ETF, namun tidak dirancang untuk menahan ratusan ribu *requests* secara serentak.
File System I/O SafetyModul Backup mengizinkan sistem menyalin data internal ke luar. Ini dibatasi ketat ke direktori fisik D:\Backup melalui pengecekan absolut os.path.commonpath untuk mencegah upaya jahat pembobolan sistem (*Directory Traversal Attack*).
Networking & SSLSistem dirancang sebagai aplikasi lokal (*Local Area Network*). Koneksi dibiarkan berada dalam skema HTTP (Port 8080). Jika ada kebutuhan untuk routing publik ke luar jangkauan LAN kantor, diwajibkan menginstal *Reverse Proxy* (seperti Nginx) guna menancapkan Certificate SSL (HTTPS) secara terpisah.

10.2 Known Limitations (Batas Fitur Berjalan)

  • Belum ada jembatan integrasi API (*Host-to-Host*) otomatis dengan sistem *Internet Banking* bank rekanan untuk proses pencairan uang secara robotik.
  • Sistem otorisasi belum menyediakan kapabilitas Pendelegasian Peran Sementara (*Temporary Role Delegation*) — misal ketika eksekutif / Releaser sedang mengambil cuti panjang.
  • Tidak ada dukungan Offline-mode atau PWA. Jika LAN putus, koneksi web app langsung berhenti.

10.3 Deployment Notes (Dokumentasi Instalasi)
