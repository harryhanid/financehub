## 1. Executive Summary / Ringkasan Eksekutif

**FLOW** (Financial Ledger and Operational Workspace — dahulu "Finance Hub") adalah sistem manajemen keuangan internal berbasis web untuk **Account Payable, Budget Monitoring, Sponsorship, Beasiswa, Bank, dan proses pembayaran**, dijalankan secara lokal (localhost/LAN). Sistem ini adalah **platform multi-perusahaan** menampung sub-modul finansial dari dua entitas: **Sinar Mas Tjipta (SMT)** dan **Eka Tjipta Foundation (ETF)**.

FLOW menggantikan sistem lama berbasis file **Microsoft Excel VBA Macro (`DbBeasiswa v2.2.xlsm`)** yang dioperasikan bersama via shared folder `Y:/`, dan sejak v2.0 juga menggantikan spreadsheet manual untuk Budget Monitoring dan Sponsorship (rekap Excel `MR`/`Rangkuman Sponsorship`). Perbandingan lengkap sistem lama vs baru tersedia di [Bagian 2.5](#25-perbandingan-sistem-excel-lama-vs-flow).

### Posisi dalam Masterplan Automasi PT Sinar Mas Tjipta

FLOW awalnya diposisikan sebagai implementasi **Fase 4 (F4) — AP, Tax & Payment** dari *Master Plan Automasi Finance & Office Management* PT Sinar Mas Tjipta. Sejak v2.0, cakupannya sudah melebar dan **juga mencakup sebagian F1 (Budget & Master Data)** — Budget Monitoring module kini live di dalam FLOW, bukan lagi sistem terpisah "TBA (Concept)" seperti didokumentasikan di v1.4.

| Fase | Sistem | Status |
|---|---|---|
| **F1** — Budget & Master Data | **Budget Monitoring module (di dalam FLOW)** | **Live** (v2.0) — sebelumnya "TBA (Concept)" di sistem terpisah |
| **F2** — Purchasing (Web Portal) | **PR Portal** (Google Apps Script) | Live |
| **F3** — Receiving & Asset Capture | SharePoint / Microsoft Lists | TBA |
| **F4** — AP, Tax & Payment | **FLOW** ← *Sistem ini* | Implemented (Beasiswa + PAM + ETF PA + Sponsorship + Bank Sahabat ETF) / Coming Soon (AP & Tax core) |
| **F5** — Accounting Hub (Posting) | Power Pivot / VBA / Power Query | Ongoing |
| **F6** — Reporting & Analytics | Looker Studio / Excel Dashboard; sebagian sudah tercakup via Dashboard BI in-app (Sponsorship, Beasiswa, Budget) | TBA / Partial |

**Alur data terintegrasi:**
```
PR Portal (F2) ──PO approved──▶ FLOW (F1 Budget + F4 AP/Payment) ──journal──▶ Accounting Hub (F5)
                                  ├── Budget Monitoring (budget vs realisasi, PO/SMT + TF/ETF cost center)
                                  ├── 3-Way Match (PO/GR/Invoice) — Fase 2
                                  ├── PPh/PPN Auto-Calculation — Fase 2
                                  ├── Payment Disbursement (CSV batch) — Fase 2
                                  ├── PAM → GL Account Posting (ETF + SMT)
                                  └── Sponsorship MR → GL upload format — Fase 1.5 (in progress)
```

## 2. Problem Statement / Latar Belakang & Tujuan

### 2.1 Masalah Sebelumnya

Sebelum FLOW, pengelolaan keuangan dilakukan dengan file Excel manual di beberapa area:

- **Beasiswa**: `DbBeasiswa v2.2.xlsm` (VBA Macro) di shared folder `Y:/` — file lock conflict, tidak ada autentikasi/audit trail, PAM manual, PAM Recon PivotTable manual.
- **Budget Monitoring**: Google Apps Script "Budget_Dashboard2" — laporan budget vs realisasi terpisah dari sistem transaksi, tidak ada carryover/additional budget workflow terstruktur.
- **Sponsorship**: rekap Excel manual per pillar/description, format "MR" (Management Report) untuk upload ke sistem GL disusun manual baris per baris termasuk nomor urut kode jurnal.
- **Bank Sahabat ETF**: mutasi rekening internal pillar SETF dicatat manual, tidak tersinkron otomatis dengan status pembayaran PAM.
- Data Sinar Mas Tjipta dan Eka Tjipta Foundation **tidak terpisah secara sistematis** di sistem-sistem lama tersebut.

### 2.2 Solusi

FLOW menyediakan (item 1-12 dari v1.x tetap berlaku; tambahan v2.0 di bawah):

1. **Portal terpusat** — semua transaksi finansial diinput dan dikelola via web app.
2. **Multi-company support** — data SMT dan ETF terisolasi secara penuh di database.
3. **Auth berbasis JWT** — hanya user yang login yang dapat mengakses sistem.
4. **Payment Approval Memo otomatis**, kini untuk **ETF dan SMT** — rekap pembayaran dari semua sub-modul dikumpulkan, diajukan, dan dimonitor dalam satu tempat.
5. **Draft Memo dengan inline editing** — memo dapat diedit langsung di browser sebelum diekspor ke PDF/Excel.
6. **Days of PAM tracking** — 4 tanggal SLA diinput langsung saat entry payment, dapat diperbarui bulk via tab khusus.
7. **Dynamic summary badges** — kartu ringkasan otomatis mencerminkan filter aktif di berbagai modul (Beasiswa, Budget, Sponsorship).
8. **ETF Payment Application (AGRI/APP/LAND/SETF)** — modul khusus tracking Payment Application beasiswa ETF dengan 7 SLA dates per PA.
9. **PAM Input Integration** — Input panel terpadu yang langsung membaca PA open, generate PAM number otomatis, update status PA secara atomik.
10. **REST API** — FLOW siap diintegrasikan ke platform induk manapun via JSON API.
11. **Export PDF & Excel** — laporan dapat diunduh dalam format standar perusahaan.
12. **Confirmation Modal** — semua aksi simpan/update/hapus memerlukan konfirmasi user via modal kustom.
13. **Budget Monitoring** *(v2.0)* — budget master, realisasi, carryover/additional budget workflow (request → approve/reject), dashboard budget-vs-realisasi per cost center (PO untuk SMT, TF untuk ETF).
14. **Sponsorship** *(v2.0, SMT-only)* — pencatatan sponsorship (Sponsorship/CSR Gedung), dashboard BI, laporan Outstanding, Rekap per pillar/description, dan format **MR** siap-upload GL (in progress).
15. **Bank Sahabat ETF** *(v2.0)* — rekening internal pillar SETF, mutasi otomatis sinkron dari status PAM (complete → masuk ledger) plus input manual, saldo berjalan.
16. **Beasiswa Dashboard BI** *(v2.0)* — dashboard analitik dalam modul Beasiswa: summary, breakdown per kategori, tren bulanan, top pembayaran terbaru, per program & pillar.
17. **Unified Navigation** *(v2.0)* — semua modul terdaftar di satu registry (`DASHBOARD_TABS`), dengan command palette (Alt+K) dan module-switcher carousel (Alt+↓) yang preview sub-tab tiap modul.
18. **PAM untuk SMT + Vendors + COA-PAM classification** *(v2.0)* — PAM tidak lagi ETF-only; SMT punya PAM lines sendiri (Advance, Energy, Fiori/APP, dll), master data Vendor, dan tabel klasifikasi `coa_pam` untuk pemetaan otomatis GL code berdasar jenis biaya.

### 2.3 Tujuan Sistem

| Tujuan | Indikator Keberhasilan |
|---|---|
| Digitalisasi data keuangan | 100% input via web, tidak ada Excel manual untuk modul live |
| Isolasi data antar perusahaan | Query apapun selalu difilter per `company_id` |
| Kontrol akses | Tidak ada halaman yang dapat diakses tanpa login |
| Payment approval terkonsolidasi | Semua pembayaran (ETF + SMT) masuk ke Payment Approval Memo |
| ETF PA tracking otomatis | 7 SLA dates per PA tercatat; PAM number auto-generate saat status → on_process |
| Status konsisten | Satu model status untuk semua tabel payment: open → on_process → complete |
| Budget termonitor real-time | Budget vs realisasi selalu up to date tanpa refresh manual pivot |
| Sponsorship siap-audit | Semua transaksi sponsorship punya jejak lengkap + format ekspor siap-GL |
| Integrasi-ready | Semua operasi tersedia via REST API JSON |

### 2.4 Non-Tujuan (Out of Scope v2.x)

- Integrasi ERP eksternal (SAP, Oracle, dll).
- Notifikasi email/WhatsApp otomatis.
- Multi-level approval workflow (approval satu tahap saja).
- Mobile native app.
- Modul Account Payable (3-Way Match), Advance (standalone, di luar PAM Advance lines), Petty Cash — masih **Coming Soon**.
- **SOP Portal** — modul baru direncanakan (index & upload/download dokumen SOP dari proyek SOP SMT-ETF), **baru tahap desain** (2026-07-27), belum ada spec/plan resmi, belum dieksekusi.
- **F2 Purchasing** — sudah ditangani PR Portal (PDO/PTA/PR/PO dengan Google Apps Script).
- **F3 Receiving & Asset Capture** — SharePoint / Microsoft Lists (sistem terpisah, TBA).
- **F5 Accounting Hub** — Power Pivot / VBA Macro (sistem terpisah, ongoing).
- Export PDF/Excel untuk halaman ETF Payment Application (belum ada, di luar Draft Memo).
- Edit siswa/lines setelah PA dibuat (integritas data).
- Sponsorship MR tab: manual edit per baris di layar (read-only by design — lihat [Bagian 11.5](#115-mr-management-report-tab-in-progress)).

## 4. User Journey Flows / Alur Pengguna

*(Alur 4.1–4.6 dari v1.4 — Login & Company Selection, Input Beasiswa, ETF Payment Application, PAM Input Integration, Payment Approval Memo, Ganti Perusahaan — tetap berlaku tanpa perubahan struktural. Alur baru v2.0 ditambahkan di bawah.)*

### 4.7 Alur Budget Monitoring

```
Dashboard [SMT | ETF]
    → Menu: Budget
    → Tab: Dashboard
        → Grafik & summary budget vs realisasi per company (cost center PO=SMT / TF=ETF), per kategori/aktivitas
    → Tab: Kelola Budget (master_list)
        → Filter: Company / Dept / Tahun / Kategori / Aktivitas / Period Mode
        → Tambah/Edit budget (Bulan, Tahun, Company, Dept, GL Account, Kategori, Aktivitas, Amount, Deadline)
        → Hapus (Releaser only)
    → Tab: Kelola Realisasi (realisasi_list)
        → Sama filter dengan Kelola Budget
        → Tambah/Edit/Hapus realisasi, terhubung ke budget_id
    → Tab: Carryover / Tambahan
        → Lihat log request Carryover & Additional Budget
        → Request baru (extension_months, reason) → status "Pending"
        → Releaser: Approve (isi extension_months) atau Reject (reason) per request
    → Export CSV: Transactions / Realization / Department Report / Expired Report / Compliance Report
```

### 4.8 Alur Sponsorship (SMT only)

```
Dashboard [SMT]
    → Menu: Sponsorship  (halaman lain menampilkan notice "Ganti Company" jika company aktif = ETF)
    → Tab: Dashboard
        → Summary cards, chart per pillar/description/cat/cat4, top 5 lembaga, YoY growth
    → Tab: Input
        → Isi: Cat (Sponsorship/CSR Gedung), Description, Tanggal Form, Cat1 (nama perusahaan → auto Cat2/Cat3),
          Lembaga/Perorangan, Perihal, Amount Request, Reff
        → Simpan → transaksi baru status open
    → Tab: Data
        → Tabel semua transaksi + filter lengkap (Cat/Cat1/Cat2/Cat3/Cat4/Description/Tahun/Status)
        → Edit inline per baris, Export Excel
    → Tab: Outstanding
        → Transaksi dengan tanggal_payment kosong, dikelompokkan per Cat2 ("Charging to ...")
        → Grand total + subtotal per grup, Export Excel
    → Tab: Report
        → Rekap per Description-section, dipivot per pillar (APP/AGRI/ENERGY & FINANCE/PROPERTY)
        → Filter: Include / BIB Include / Exclude / All (cat4), multi-select Tahun
        → Export Excel format standar "RANGKUMAN SPONSORSHIP"
    → Tab: MR (Management Report) — in progress, lihat §11.5
        → Filter Tahun saja → tabel 17-kolom read-only siap-GL, Export Excel
```

### 4.9 Alur Bank Sahabat ETF (ETF only)

```
Dashboard [ETF]
    → Menu: Bank
    → Tampilan: Open PAM SETF (belum sync) + Mutasi & Saldo (bank_setf, filter Bulan/Tahun)
    → Sinkron otomatis: setiap PAM SETF berubah status (open→on_process→complete, revert, atau edit nominal
      setelah complete) → bank_setf di-insert/update/delete idempotent (source='pam')
    → Input manual: tambah/edit/hapus transaksi pemasukan/pengeluaran non-PAM (source='manual')
    → Saldo berjalan (running balance) dihitung dari seluruh riwayat mutasi
    → Export "Laporan Mutasi Bank Sahabat ETF" (Excel)
```

### 4.10 Alur Beasiswa Dashboard BI

```
Dashboard [ETF]
    → Menu: Beasiswa → Tab: Dashboard
    → Filter: Tahun / Pillar / Program / Jenjang (dropdown chip seragam)
    → Panel: Summary (total budget/payment/siswa), Breakdown per kategori,
      Trend bulanan, Latest Payments (top 10, atau top 30 per kategori jika di-drill),
      Program Summary, Pillar × Tahun chart
    → Semua panel filter-aware — ganti filter, semua chart re-fetch via /api/dashboard/*
```

### 10.5 Carryover & Additional Budget Workflow

```
request_carryover(budget_id, username, reason)
  → INSERT budget_carryover_logs (type='Carryover', status='Pending')

request_additional_budget(budget_id, username, amount, reason)
  → INSERT budget_carryover_logs (type='Additional', status='Pending', additional_amount)

Releaser:
  approve_carryover(budget_id, username, extension_months) → status='Approved', extend deadline
  approve_additional_budget(budget_id, username, extension_months) → status='Approved', tambah amount ke budget
  reject_request(budget_id, username, reason) → status='Rejected' (type-agnostic — berlaku utk Carryover & Additional)
```

Satu `budget_id` hanya boleh punya 1 request **Pending** aktif kapan pun (divalidasi di service layer) — inilah yang membuat `reject_request()` aman dipakai generik untuk kedua tipe di route `additional_reject`.

CREATE TABLE IF NOT EXISTS budget_master (
